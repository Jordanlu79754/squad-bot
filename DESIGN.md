The Discord library was imported into this project for the use and access of relevant Discord commands. Dotenv was imported for privacy reasons using github. The Discord bot's API token is a very sensitive piece of information that should not be hardcoded into the code especially for any projects that will be made public. I also imported os, random, csv, yt_dlp, and asyncio to make some of my functions possible. Without them, some components of this project would not have been possible. I needed os to delete audio files after downloading them and using them through FFmpeg, random was very helpful in determinign which random prompt can be used for truth or dare and magic 8 ball. yt_dlp and asyncio was necessary for all of the music related features such as downloading the songs and all of the features related to the queue. CSV was espeically important in the creation of the Country Trivia game, it made it possible for me to find a database with the information I had needed and made accessing them very convinient.

This was my first time doing a project like this. I had ran into many errors and problems that were not obvious to identify and let alone try to debug. The on_command_error feature was one of the most useful tools that was implemented. It would help me identify if the command I had programmed was the problem or something else under the hood. Sometimes the terminal would return nothing and identify that the music playing feature was working but no actual music was played. This command returned some sign of failure to the Discord and helped me through the debug process.

Discord is one of the applications where you cannot trust user input at the slightlest. People will spam and abuse commands for Discord bots in an attempt to 'troll' others or for things not intended for their purpose. In this case, I added many error checks throughout the code to limit the possibility of this. For example, any voice related activity such as playing music must require the user who is requesting a song to be in the voice channel. This served 2 purposes: 1, a specific location for the bot to know where it needs to go and 2, people cannot play audio to a group of individuals that they are not currently in a call with. Additionally, important regarding how information was used was made very clear. The purpose of such was to help me understand how files were being used, deleted, and if they were being processed the way I had intended them to.

The song queue was a feature that took a lot of thought and time. It required the asyncio library to be imported in order to be used. 'Events' had to be scheduled after a song was played to ensure that it will properly get deleted and that the next song will be automatically played. Some syntax and usage of asyncio was very hard to figure out and with the assistance of ChatGPT it runs smoothly and properly. Working with scheduling events to be executed in real time and implementing additional features such as prioritize was definitely an interesting experience.

I implement many messages feedback that was also printed to the user when commands worked or not. For example, when playing a song and whenever a new one is played, the youtube preview with link is displayed. This ensures that the right song is played and was especially useful when ensuring if the search actually went through. Additionally, an error message would be returned if the user entered an invalid input for commands like truth or dare. 

For Discord applications, ctx is a very important part of the code to be included in any sort of text based responses. It records the user that sent a message or request's information such as text channel/voice channel and will send a proper response message or response command to the correct location. Additionally, it ensures that the correct user is being prompted or responded when multiple users use commands at the same time.

Outside of user related checks, error checks and time checks for everything is necessary for both stability reasons and debugging purposes. For many commands that require user response/input, a timer was set and after that timer if the user had not responded, it will terminate the program ran by the command automatically. Closing and checking that a prompt is not left unanswered/unresponded will ensure the program runs smoothly and without additionally burden.
